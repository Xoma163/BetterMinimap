# Better Minimap — инструкции для работы с проектом

## Проект и границы изменений

- Клиентский мод Valheim, C# / Unity / BepInEx 5 / Harmony / TextMeshPro. Основная сборка — `net48`, математические тесты — `net8.0`.
- GitHub: `https://github.com/Xoma163/BetterMinimap`, основная ветка `main`.
- Thunderstore: `https://thunderstore.io/c/valheim/p/AndrewSha/BetterMinimap/`, команда **AndrewSha**, пакет **BetterMinimap**. Это основная площадка распространения, не CurseForge.
- Стабильный ID плагина: `net.shtab.rotatingminimap`. Не менять ID, имя DLL `BetterMinimap.dll` и путь конфига без отдельной задачи.
- Не изменять сохранения мира, исследование карты и сетевой протокол ради HUD. Не добавлять серверную зависимость.
- Пользователь предпочитает короткие ответы на русском и готовый ZIP для ручного импорта в r2modman. Всегда указывать полный локальный путь к выданной сборке.
- Вопрос/обсуждение дизайна не означает команду менять код. Не устанавливать сборку в живой профиль, не коммитить, не пушить и не публиковать без соответствующего поручения. После поручения на публикацию выполнять весь согласованный процесс, а не только создавать архив.

## Сборка и проверки

Работать из корня репозитория. В текущем окружении обычный `dotnet` ранее не находил SDK; проверенный SDK лежит в каталоге OpenCode. Пути локальные, перед использованием проверить их существование:

```powershell
$dotnet = Join-Path $env:LOCALAPPDATA 'Temp\opencode\dotnet-sdk\dotnet.exe'
$game = 'C:\Program Files (x86)\Steam\steamapps\common\Valheim'
$core = Join-Path $env:APPDATA 'r2modmanPlus-local\Valheim\profiles\SHTAB-SORTIR\BepInEx\core'

& $dotnet build RotatingMinimap.csproj -c Release "-p:ValheimDir=$game" "-p:BepInExCore=$core"
if ($LASTEXITCODE -ne 0) { throw 'Build failed' }
& $dotnet run --project tests/GeometryTests.csproj -c Release
if ($LASTEXITCODE -ne 0) { throw 'Tests failed' }
git -c core.autocrlf=false diff --check
if ($LASTEXITCODE -ne 0) { throw 'Diff check failed' }
powershell -NoProfile -ExecutionPolicy Bypass -File package.ps1
if ($LASTEXITCODE -ne 0) { throw 'Packaging failed' }
```

- Выход: `bin/Release/net48/BetterMinimap.dll`; архив: `artifacts/AndrewSha-BetterMinimap-<version>-r2modman.zip`.
- `local.props` может задавать пути ссылок, но не должен попадать в Git. Игровые DLL и декомпилированный код также не коммитить и не включать в пакет.
- `package.ps1` **не компилирует DLL**: сначала собрать Release. Он проверяет совпадение версии DLL/manifest, кладёт текущие README/CHANGELOG/LICENSE и генерирует иконку 256×256. Существующий ZIP той же версии перезаписывается.
- Новые чистые математические/helper-файлы нужно явно подключать в `tests/GeometryTests.csproj`; основной проект включает `src/**/*.cs` автоматически.
- CI `.github/workflows/tests.yml` запускает только тесты, **не полную сборку DLL**: в GitHub Actions нет локальных библиотек Valheim. Не называть приложенный локальный ZIP «собранным в GitHub Actions».
- Автотесты не запускают Unity. Отрисовку, маски, ввод, переключение карт и совместимость проверяют в игре по `docs/testing-hud-navigation.md`. В ответе отличать успешную компиляцию от визуальной проверки.

## Версии, документация и релизы

- Синхронно менять версию в атрибуте `BepInPlugin` в `src/Plugin.cs`, `<Version>` в `RotatingMinimap.csproj` и `version_number` в `package/manifest.json`.
- Перед выбором номера проверить опубликованные версии GitHub/Thunderstore. Последний релиз на момент создания этого файла — **1.1.1**; это историческая отметка, не источник актуальной версии.
- Пользователь объединяет несколько локальных тестовых сборок в один итоговый релиз. Не считать промежуточные номера уже опубликованными. По его указанию объединять заметки в один changelog относительно предыдущего публичного релиза, описывая конечное поведение, а не отменённые эксперименты.
- Обновлять README на русском и английском, CHANGELOG и ручной checklist. Для изменения только документации/`AGENTS.md` не нужна новая версия мода.
- При будущих обновлениях оформлять changelog в свёрнутых блоках (`<details>` / `<summary>`). Текущий changelog отдельно ради этого не переделывать: пожелание относится к дальнейшим изменениям.
- В README история версий — раздел **Changelog** с отдельным закрытым `<details>` для каждой версии в обоих языках, без открытых заголовков «What's new…». Разделы настроек и HUD оставлять краткими: основные дефолты и управление, без повторов и технических подробностей. Инструкции сборки — в `docs/building.md`.
- В README ровно **одно встроенное изображение**: `docs/images/reference.png`, **выше Changelog**; русский раздел ссылается на него, не дублирует.
- **Не удалять старые `docs/images/circular.jpg`, `square.jpg`, `ship-zoom.jpg`**: README опубликованных архивов ссылаются на эти файлы через `raw.githubusercontent.com/.../main/...`. Они остаются для совместимости ссылок, не для новой галереи.
- Для нового референса использовать именно последний выбранный пользователем файл, а не похожий старый скриншот или содержимое буфера обмена.

### GitHub (когда поручено)

1. Проверить `git status`, diff и remote; получить обновления без перезаписи пользовательских изменений.
2. Собрать, протестировать и упаковать итоговую версию. Проверить в ZIP manifest, README/CHANGELOG и совпадение SHA-256 DLL с Release-сборкой.
3. Сделать коммит относящихся к задаче файлов и пуш. Не добавлять `bin`, `obj`, `artifacts`, игровые библиотеки или секреты.
4. Создать релиз `v<version>` на точном SHA коммита с RU/EN-заметками из CHANGELOG. Безопасный порядок: draft → загрузить ZIP → проверить размер/hash → опубликовать. При существующем теге/релизе сначала выяснить состояние; не перезаписывать его молча.
5. Проверить опубликованный asset, ссылку релиза и результат Actions. Пуш коммита и создание тега могут запустить два тестовых workflow.

### Thunderstore (когда поручено отдельно или явно включено в задачу)

- При отсутствии авторизации открыть сайт в доступном пользователю браузере и попросить войти. Не просить прислать пароль, не записывать cookies/токены в репозиторий, логи или ответы.
- Через **Upload** (`https://thunderstore.io/package/create/`) загрузить готовый ZIP без распаковки. Команда **AndrewSha**, сообщество **Valheim**, NSFW выключен.
- Сохранить категории: **AI Generated, Client-side, Mods, Tweaks, Utility**. Пакет с тем же именем под той же командой получает новую версию; новый проект не создавать.
- Перед Submit проверить команду, игру, имя/размер архива и категории. После отправки не нажимать Submit повторно, пока не выяснен результат.
- Подтверждать публикацию не только по UI: публичный API `https://thunderstore.io/api/experimental/package/AndrewSha/BetterMinimap/` показывает `latest.version_number`, активность и категории. Скачать `latest.download_url` и сравнить SHA-256 с отправленным ZIP.
- **Thunderstore берёт README/CHANGELOG из ZIP, не из GitHub.** Исправление README только в репозитории не обновит описание опубликованного пакета.
- Страница Thunderstore может кешировать старую версию даже после успешной загрузки. Сначала проверить API и содержимое скачанного ZIP. Проверенный обход кеша страницы: `?v=<version>`. Не выпускать лишнюю версию и не обвинять пользователя в неправильном архиве без проверки.

## Настройки и совместимость конфига

- `src/SettingsLayout.cs` — единый источник групп и порядка 39 текущих настроек (1.2.0):
  1. Общее — мод, мини-карта, кнопки сброса.
  2. Вид карты — форма, размер, освещение, прозрачность, вращение, режим.
  3. Масштаб и управление — зум, отдельный зум корабля, дополнительные клавиши.
  4. Элементы вокруг карты — шесть слотов и шесть индивидуальных размеров.
  5. Компас и навигация — направления/линии, цель, справка о пингах.
  6. Игроки — никнеймы, размер шрифта, обводка.
  7. Транспорт — показ и размер иконок.
- `SettingsText.cs` отвечает за RU/EN-представление, `ModManagerBridge.cs` — за необязательную интеграцию со StoreAndCraft. Патчи UI должны затрагивать только страницу/настройки этого мода.
- Конфиг: `BepInEx/config/net.shtab.rotatingminimap.cfg`; память зума: соседний `.cfg.zoom`. Ручное редактирование — при закрытой игре.
- Стабильные ключи часто русские. Для переименования подписи сохранять ключ: например, **«Зум через доп. клавиши» / “Zoom with extra keys”** использует старый ключ `Зум через + и -`.
- Миграции в `Plugin.cs`: сначала старые схемы, затем `Regroup`/`RebindSection`. Сохранённое значение в новом разделе имеет приоритет над старым; повторный запуск не должен возвращать дефолты. Не превращать пользовательское значение в `DefaultValue`.
- Сохранить диапазоны, описания, привязки клавиш и выбор слотов. При добавлении/переносе настройки обновлять layout, локализацию, presets и тесты.
- Изменения в окне применяются после **Сохранить**; Close/Back отменяет несохранённое. Оба пресета сохраняют общий выключатель мода, включая его несохранённое значение. Кнопки сброса находятся в «Общем».

## Согласованное поведение HUD

- Слоты: **1 → 2 → карта → 3 → 4 → 5 → 6**, дефолты **Пусто / Биом / Ветер / Пусто / Пусто / Пусто**. Пустые строки не занимают место; повторение содержимого разрешено. Число слотов задаёт `HudSlots.Count`.
- Индивидуальный размер слота **25–400%, дефолт 100%**, включая биом и ветер. При 100% все тексты имеют штатный размер шрифта биома (фиксированный шрифт 9 для координат остался в 1.1.1). Размер сохраняется независимо от содержимого; оба пресета возвращают 100%. Ключи `Размер текста Slot N` стабильны. В StoreAndCraft содержимое и размер объединены в строку; узкое окно — две строки. Не менять чужие страницы и штатные обработчики Save/Cancel.
- Координаты включаются выбором в слоте, **без отдельного переключателя**. Чёрная обводка **3 пикселя**, **без прямоугольной подложки** — пользователь её отверг. Размер одного слота не влияет на остальные.
- Ветер по центру над/под картой, при 100% штатного размера; масштабировать от сохранённой native-базы, не накапливать масштаб по кадрам. Строка учитывает диагональ стрелки. Биом сохраняет штатный шрифт, строка учитывает метрики текста и не наследует временную прозрачность native-анимации.
- Содержимое `Time` — игровые солнечные часы, `RealTime` — местные часы компьютера, оба HH:mm; `Weight` — текущий вес / грузоподъёмность с округлением вверх как в инвентаре. Белый текст, обводка 2 пикселя, без подложки. Не менять сохранённые enum ID и не добавлять серверные запросы.
- Прозрачность **0–100%, дефолт 0%** меняет только фон мини-карты. При 1–99% — отдельный проход native-шейдера, при 100% фон скрыт, при 0% дополнительные ресурсы освобождаются. Значки, рамка, компас, слоты и большая карта не меняются. `TransparencyFallback` изолирует сбой: непрозрачный фон, одно предупреждение, настройка сохранена, повтор после 0% → нужное значение. Проверять восстановление native UI и освобождение ресурсов.
- Одна тонкая **коричневая** рамка, без дополнительной чёрной обводки. `MapFrameGeometry`, `MapMaskGraphic`, `MapShapeView`, `MapBorderView` используют согласованную геометрию. Не возвращать 128px alpha-маску: её край выступал за рамку.
- Иконки игроков выше остальных иконок/надписей на обеих картах, своя стрелка выше всех. `PlayerIconLayer` временно переносит native-иконки и **восстанавливает родителей/положение до следующего обновления игры**: иначе `UpdatePins` пересоздаёт их. На выключении/смене мира всё восстановить; не ломать маски и ввод.
- Никнеймы только **других игроков с открытой позицией**, близко под иконкой. Своё имя не показывать. Размер **4–20**, дефолт **8**; отключаемая обводка **2 пикселя**. Подписи большой карты не заменять.
- Транспорт: тележки `Vagon`, плоты/корабли `Ship`, включая припаркованные и модифицированные на стандартных компонентах. Показ на обеих картах, дефолт On; размер **5–20**, дефолт **12**, не влияет на игроков. Только загруженные клиентом объекты, не глобальный поиск. Не обещать поддержку полностью нестандартных компонентов транспорта.
- Для транспорта не создавать сохранённые пины и сетевые запросы, не дублировать штатный маркер управляемого корабля. Выключение самого мода восстанавливает native-маркеры. Уничтоженные/выгруженные объекты исчезают.
- Цель локальна текущему сеансу: Shift+ЛКМ по любой точке M задаёт/переносит, Shift+ПКМ снимает **без удаления пинов**. Подтверждение с округлённым горизонтальным расстоянием. Обычные действия с пинами сохраняются.
- Пинги, не помещающиеся на мини-карте, — синие стрелки той же формы, что у золотой цели; ближние — штатные кольца. Использовать native-списки/время жизни пингов.
- Скрытие мини-карты — обратимый `CanvasGroup` через `MinimapVisibility`, **не смена MapMode**. Большая M остаётся доступной; общий выключатель восстанавливает штатный HUD.

## Важные технические ловушки

- В установленной версии TMP числовой `SetText` оставляет `m_text` старым: первое чтение `.text` материализует backing buffer и сбрасывает dirty-флаг, последующие могут вернуть старую строку. Так пропадали копии обводки координат. Координаты используют кешированную строку через **`.text = ...`**, а `ExternalTextShadow` читает источник **один раз для всех восьми копий**. Проверять и движение, и неподвижное состояние, и смену содержимого слота.
- Общие материалы шрифтов/карты не менять глобально. Собственные материалы, графику и состояния native-UI освобождать/восстанавливать через lifecycle/Dispose, включая ошибки и выключение мода.
- `Minimap.SetMapMode` может досрочно выйти при неизменном режиме. Не полагаться на повторный вызов для восстановления скрытого HUD.
- Harmony/API проверять по установленным DLL, не угадывать сигнатуры. В локальном `...\Temp\opencode\` ранее сохранены `BetterMinimap-Minimap.cs`, `BetterMinimap-Ship.cs`, `BetterMinimap-Vagon.cs`, `BetterMinimap-TMP_Text.cs`; там же `ilspy-tools\ilspycmd.exe`. Это вспомогательные файлы, после обновления игры они могут устареть.
- После UI-изменений проверять обе формы карты, все режимы вращения, M ↔ мини-карта, размеры HUD/карты, Off/On, смерть/возрождение и смену мира. Не исправлять локальную проблему изменением размеров/стилей всех элементов сразу.
